# Data provenance

## Independently generated inputs

`scripts/make_synthetic_data.py` generates data entirely from a NumPy random-number generator. It does not download data or read external expression matrices, presentations, images, marker panels, or research results.

The default simulation creates 360 cells, 600 features, and 180 empty droplets with seed 7. These dimensions are arbitrary software-demo settings. Three artificial populations have elevated counts in distinct feature ranges, and two artificial batches have a modest invented expression effect. Artificial ambient counts are added to the cell matrix. Additional low-count droplets supply a background profile for the SoupX example.

Features use `Gene0001`-style names. Cells use `SIMCELL0001`-style names; background droplets use `EMPTY0001`-style names. The first 15 features form an invented QC proxy. They have no biological identities.

The generator writes the origin tag `independent_simulation_v1`, its seed and dimensions. Simulation labels describe how counts were generated, not annotations inferred from a real dataset.

## Public content

Public files comprise new demonstration code, installation instructions, tests, documentation, and a figure generated by the Python example. No original research inputs, slide images, sample metadata, biological gene panels, experimental results, or existing research scripts are included.

The scripts check artificial identifiers and simulation provenance. The Python reader rebuilds its AnnData object from a small set of allowed fields, preventing unrelated annotations and hidden metadata from being carried into its outputs. These checks reduce accidental mixing of inputs; an identifier or provenance tag is not cryptographic proof that a matrix is synthetic. Renaming real data would not make it safe to publish.

## Reproducibility and limits

The Python dependencies are pinned to the executed demonstration environment. Analysis steps record parameters and package versions. R scripts record `sessionInfo()` when run. UMAP coordinates and clustering can vary between software builds or platforms despite fixed seeds.

The figure in `assets/` is explicitly selected from the simulated Python run. Generated count matrices and routine outputs are ignored by Git. The repository makes no biological or clinical claims.
