# Data and code provenance

## Research code excerpts

The research code is organized into three project pages, with a [complete code index](CODE_INDEX.md). The three HCC notebooks in `workflows/` come from Mohua Das's own R analysis notebooks. The additional files under `projects/` are edited excerpts from code she supplied as used in her analyses, including adapted and shared workflow patterns. Where a source gives an explicit author or tutorial credit, that attribution is preserved. Inclusion does not imply sole authorship of every upstream routine or input object.

The current release includes selected excerpts from 10 additional Python/R source files: seven for the CRTi project and three for the human endothelial-cell project. The supporting DESeq2 script is bulk RNA-seq analysis, not a single-cell workflow. A figure-only PDF supplied with the sources is not published.

Project mapping follows the clearly associated sections of the working files. Some exploratory notebooks contain blocks from different analyses. Blocks whose project context could not be established are excluded from this release. Tool claims reflect actual calls in retained code. In particular, the scVI model example does not supply a batch key, and a second endothelial Python notebook implements PCA rather than scVI training.

Editorial changes include neutral object names and local paths, replacing private selections with configuration inputs, stripping all Jupyter outputs and metadata, consolidating repeated trial blocks, and small consistency fixes documented in the files. Study-specific marker panels, annotation assignments, sample-to-condition mappings, biological conclusions and recorded dataset dimensions are not distributed.

These are not executable reproductions of the underlying studies. They require private matrices, AnnData/Seurat objects or locally supplied annotation/configuration files. The edited analyses have not been rerun with those inputs. R Markdown analysis chunks are disabled by default, and the human Python notebooks include disabled execution flags. The CRTi Python sequence documents private inputs and can execute only when those are supplied. Raw and processed data, model weights, original presentations and the new figure PDF are not included.

## Selected real analysis figures

`assets/research/clustering-overview.png` and `assets/research/subset-reclustering.png` are selected figures from Mohua Das's own HCC analysis, shared with her explicit approval. They show real UMAP embeddings with numbered clusters. Biological labels, sample assignments, and experimental comparisons are not shared.

The plot pixels are unchanged from the original images. Embedded EXIF, XMP, and device-profile metadata have been removed. These images are real archival outputs, not synthetic examples or figures regenerated by the edited public notebooks. Reproducing them would require the private data and original analysis environment.

## Separate synthetic examples

The files in `scripts/`, the Python tests, and `assets/synthetic_umap.png` are new portfolio demonstrations. They are separate from the research notebook excerpts.

`scripts/make_synthetic_data.py` creates counts entirely from a NumPy random-number generator. It does not download data or read external expression matrices, presentations, marker panels, or research results. Its default dimensions and parameters are arbitrary demo settings.

Features use `Gene0001`-style names. Cells use `SIMCELL0001`-style names; background droplets use `EMPTY0001`-style names. Population and batch labels are invented. The first 15 features form an artificial QC proxy and have no biological identities.

The generator writes the origin tag `independent_simulation_v1`, its seed and dimensions. The synthetic readers validate artificial identifiers and permitted metadata. Those checks reduce accidental input mixing; a tag is not proof that an arbitrary matrix is synthetic. Renaming real data would not make it safe to publish.

## Public files and local outputs

Research inputs belong in ignored `data/` or `local_inputs/` directories; notebook-specific private outputs also remain ignored. Routine outputs, generated matrices, notebook HTML, and serialized analysis objects stay local. The committed images comprise only the two previously approved HCC figures and the separately labeled synthetic Scanpy preview. No new plots or figures from the CRTi or human endothelial-cell projects are included. Any future research-figure release requires separate review and author approval.

Seeds and package versions are recorded by the synthetic scripts. The Python requirements pin direct dependencies from the executed example. The R installer is not a lockfile, and the research notebooks do not have a validated public execution environment.
